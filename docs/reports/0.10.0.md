# 0.10.0 — scoped inbox, durable review/cancellation and a compaction example

This release folds together four accepted, independently reviewed changes and
packages one dormant prototype as a documented example. It is a release and
packaging change: it adds no new public `complete_agent`/workspace API, enables
no automation and does not activate compaction.

## What shipped

### Scoped notification inbox (`src/notifications.mjs`, `src/review-packets.mjs`)

`receive_notification` reconciles exactly the member reports of the *current*
notification envelope instead of sweeping the whole chat inbox. Unrelated
receipts and future wakes are left untouched, and an already-received envelope
replays deterministically without duplicating effects. The durable review packet
captures that set as bounded, replayable evidence bound to a stable batch; it
never acknowledges, accepts, replies to, retires or signals a worker.

### Durable review packets and revision-bound reviews (`src/review-packets.mjs`, `src/revision-reviews.mjs`)

A review packet records *which reports the manager received while handling one
notification and what each claimed*. `src/revision-reviews.mjs` binds an
acceptance to the exact content revision, worker, task, chat, launch and
activation that produced the result, so a decision can be replayed after a
restart and later drift is observable via the read-only `verify_review`. The
`capture_review`, `verify_review` and revision-bound `resolve_message` tools wire
the first, deliberately narrow slice of this over the existing MCP surface.

### Owner-scoped request cancellation (`src/requests.mjs`, `src/delegation.mjs`, `src/cli.mjs`, `src/agent-tools.mjs`)

`agent cancel-request` / the `cancel_request` MCP tool retires an **unclaimed**
outbound operation. The caller must pass the exact owner manager chat UUID with
`--thread`; it is compared against the target agent's registered task thread
*before* the request row is read, so a different chat is refused as
`Not your request`. An atomic `--expected-state` precondition guards the
transition, ineligible/refused states are named, and an identical replay is
idempotent. The disposition identity (`--request-id`) is separate from the
retired operation (`--target-request-id`).

### Bounded-compaction example, shipped dormant (`recipes/compaction/*` → `examples/compaction`)

A reviewed bounded compaction **summary-candidate** recipe, its JSON schema, a
canonical single-line JSON parameter encoder and the integration contract are
packaged as a documented example. The recipe produces a candidate only: it never
applies the summary, never rewrites the transcript and never issues lifecycle or
native commands. The adapter owns session identity, input digest,
`firstKeptEntryId` and `tokensBefore`, and refuses non-canonical/lossy input
before a run.

**This example is not wired in.** The adapter modules require a caller-supplied
absolute `recipePath`; the packaged example assets are not copied into a durable
runtime snapshot and are not activated. Live qualification and explicit durable
asset selection remain required, and no live compaction success is claimed.

## Packaging (`scripts/build-plugin.mjs`)

- The builder now packages exactly four compaction assets under
  `examples/compaction` — `recipe.yaml`, `schema/summary-candidate.schema.json`,
  `lib/param-encode.mjs`, `integration-contract.md` — and **no test fixture
  tree**.
- It asserts all four expected assets exist after staging and that the packaged
  `runtime/src/compaction-service.mjs` and `runtime/src/pi-compaction-extension.mjs`
  modules import from their own runtime copy.
- The former directory-wide YAML allowance is narrowed to an explicit allowlist of
  reviewed example files; all other file-extension, private-content and
  document-link scans are preserved.
- Canonical MCP discovery is unchanged: the packaged server must return exactly
  the `AGENT_TOOLS` name set (`spawn_agent` … `verify_review`, sixteen tools),
  derived from the single exported source of truth rather than a hand count.

## Verification

The package builder was run to a fresh scratch destination (no model calls). It
passed file inventory, private-content scan, document-link validation, packaged
CLI help, packaged MCP discovery (sixteen tools), the new compaction-asset
existence check and the packaged-module import check, and produced a
`BUILD-MANIFEST.json` plus a `.tar.gz` archive.

The focused suites for the four accepted changes were run by the maintainer at
their integration checkpoints (scoped inbox, review/status, cancellation and the
compaction recipe with native Goose rendering). Where a review sandbox forbids
binding the bridge's absolute Unix socket (`listen EPERM`), the IPC-dependent
suites cannot complete there and fail only with that sandbox error; the
maintainer's clean-environment full run is the release result. A socket fixture
blocker is reported once and is not re-chased with repeated full suites.

## Boundaries (documented, not invented)

- Packaging the compaction example does not activate it and does not prove live
  summarization. Model/provider selection, durable asset copying and hook wiring
  remain explicit future work.
- Review packets and revision reviews are evidence and binding only; they do not
  schedule, launch, acknowledge or retire workers.
- Request cancellation does not terminate a process; it retires an unclaimed
  outbound operation under an exact owner and state precondition.
