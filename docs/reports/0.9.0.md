# 0.9.0 — truthful steering, interruption and intentional stop

Implemented on 2026-11-13. Supersedes [0.8.2](0.8.2.md) for delegation behavior.
The durable runtime snapshot, provider/model preservation, bridge lock/ownership,
writer leases, thread ownership, notification inbox and host-queue protocol are
unchanged. This release fixes the delegation/lifecycle layer only.

## Reported problems

1. A steering note returned `state=sent` / `status=working` even though the model
   never acted on it. Managers read that as "the model consumed my instruction".
2. `interrupt_agent` returned a native outcome of `still_working`, and an
   immediate follow-up also reported `sent` — so a later assignment appeared to
   overtake an unresolved interruption.
3. A deliberate native kill of `t1w` was quarantined as a runtime fault, because
   nothing recorded that the exit was intentional before the process ended.
4. A manager could not safely end its turn: own-send activity woke `wait_agent`
   prematurely, and there was no single event that reliably woke the exact
   existing chat on a result, question or intentional stop.

## Root cause

- Delivery used one word (`sent`) for three different facts: the note was durably
  queued, the native transport accepted the input, and the model actually
  consumed it. Only the middle fact was known.
- Interruption trusted the request receipt instead of re-observing the original
  native identity/turn.
- Stop had no durable record of intent before the kill, so the bridge could only
  classify the exit as an unexpected loss.
- The default bridge wake set omitted the stop lifecycle events.

## Changes

### Truthful delivery receipts (`src/requests.mjs`)

Every request now carries an explicit `delivery` value:

| value | meaning |
| --- | --- |
| `queued` | durable only; not yet sent |
| `native-injected` | native transport accepted the input; consumption **not** confirmed |
| `confirmed` | observed evidence recorded by an operator |
| `refused` | terminal non-delivery |
| `uncertain` | an attempted send whose outcome is unknown |

`finish` derives `delivery` from the state; native send success writes
`native-injected` with an explicit note that consumption is unconfirmed. A note
carried on an accepted follow-up is recorded `attached` (distinct from durable
`queued` and inline `native-injected`). The intentional-stop path adds
`stop-requested`, `confirmed-stopped`, `already-exited` and `unattributed-exit`.
`reconcile` upgrades an existing `sent` record to `confirmed` from actual
evidence in a transaction and journals `agent.request.confirmed`; it never
performs a second native send. Empty/non-string evidence is refused.

### Confirmed interruption (`src/delegation.mjs`)

`interrupt` no longer trusts the request receipt. After `terminal.interrupt` it
re-reads `terminal.get` and validates the response against the recorded original
native identity (address, pid, argv, task/desk labels and any adopted immutable
identity). It confirms only when that *validated original* terminal is observed
`idle` or `done`, or its state is `finished`. A vanished terminal (`not_found`)
is **not** proof that the original turn stopped: it is recorded as `gone` and
the request stays `uncertain` and blocks later input (see ordering below). The
record stores `interruption.{outcome,confirmed,gone,turnBefore,turnAfter,pid}`.
A confirmed interrupt retains the session and writer lease; the native harness
governs how a working agent processes steering.

### Intentional stop (`src/delegation.mjs`, `src/cli.mjs`, `src/agent-tools.mjs`, `src/agent-mcp.mjs`)

New `agent stop --id KEY --request-id KEY [--note TEXT]` CLI action and
`stop_agent` MCP tool. A recorded stop *intent* is never by itself proof of a
deliberate stop. The sequence is:

1. reserve the request (`stop`) and write `stop:<id>` meta plus
   `agent.stop.requested` **before** any kill, with an explicit durable
   `dispatch` state (`not-dispatched`);
2. `terminal.get` + `assertNativeWorker` to bind the exact original process;
3. only when that terminal is `live`, mark `dispatch:'dispatching'` **before**
   awaiting `terminal.kill`, then record the receipt: `accepted` on an
   acknowledged signal, `refused` for a recognised native refusal, `uncertain`
   for an unknown/transport failure. A kill is never issued against a changed
   identity and never by pattern;
4. `confirmStop` re-observes the original process. Only a validated `finished`
   state for the recorded identity releases the writer lease, marks
   `launchState:'stopped'`, writes the single `agent.stopped` audit row and one
   lifecycle notice, and refuses later input.

Attribution is derived only from the durable dispatch record, and is frozen on
the first confirming settlement so a replay cannot rewrite the story:

| dispatch | observed original exit | attribution |
| --- | --- | --- |
| `accepted` | `finished` | `intentional` |
| `not-dispatched` and original already finished | `finished` | `already-exited` |
| `refused` / `uncertain` / `dispatching` | `finished` | `unattributed` |

An in-flight `dispatching` signal is **not** acceptance: if the original is
observed `finished` while the kill receipt is still outstanding, the stop is
settled conservatively as `unattributed` on the first observation (one durable
honest wake); a later `accepted` receipt is recorded as separate dispatch
evidence and never rewrites the delivered verdict. A late native refusal or
unknown error is likewise retained durably (`dispatchError`) without a second
notice or a fabricated accepted signal. The whole confirmed transition — worker
stopped state, writer-lease release, stop metadata, request receipt, the
`agent.stopped` audit row and the lifecycle notice — commits in one transaction,
so a crash cannot half-stop a worker or lose the wake. Raw exit evidence is kept
separately from the classified verdict. A vanished terminal (`gone`) is never
proof of exit and never yields `confirmed-stopped`.

Retrying the same `--request-id` re-checks confirmation (`sending`/`uncertain`)
instead of killing again; a concurrent retry that has already settled returns the
settled record while still recording late native evidence. A replaced process
(`process_replaced`, an explicit identity mismatch) is never excused by stop
intent and still faults; the shared validator is applied to both `live` and
`finished` originals, so a replacement can never confirm the original's stop or
release its writer lease. A missing or replaced process faults and retains the
reservation; a verified original finished exit permits lease release and is
still reported as a fault when unexpected.

### Ordered follow-ups

`Requests.claim` serializes per-agent delivery with two independent barriers:

1. **In-flight barrier (order-independent).** Any *other* request currently in
   `sending` or `uncertain` blocks ordinary delivery, regardless of when it was
   reserved. This covers a later-reserved interrupt whose turn is still running
   and an inline `message` whose native receipt was lost. Durable notes stay
   `queued` until claimed, so they do not trip the barrier; they are attached to
   the next delivery instead.
2. **Prepared predecessor ordering (order-dependent).** An ordinary assignment
   also waits for an *earlier-reserved* (`prepared`) operation. A later prepared
   request never blocks an earlier one, so a follow-up that was refused while the
   initial was awaiting readiness cannot deadlock it.

The initial-assignment guard is separate: a second `initial` cannot overtake an
undelivered first `initial`. Lifecycle exceptions are per request code, not
positional: `stop` bypasses every barrier (it is how a wedged turn is ended) and
is never itself overtaken; `interrupt` bypasses unresolved normal input but never
another unresolved interrupt. An unresolved interruption blocks a normal
follow-up until it is reconciled; a confirmed interruption permits later
delivery, while a stopped agent refuses later input.

### Event-driven bridge wake (`src/activity-wait.mjs`, `src/bridge.mjs`)

`DEFAULT_ACTIVITY_TYPES` now includes `agent.stopped` alongside the existing
request outcomes and `agent.interrupted`. It deliberately **excludes**
`agent.stop.requested`: that is the manager's own administrative request, and a
manager that issued the stop and then yielded must not be woken by its own
outbound control — only the confirmed `agent.stopped` is wake-worthy. The bridge
publisher is type-agnostic (it just notifies after commit), and `waitForAgentActivity`
filters committed journal rows by type and worker/agent id. No polling, interval
or scheduled manager is introduced.

### Bridge stop-vs-fault routing (`src/bridge.mjs`)

Before classifying an exit, the bridge validates the observed terminal against
the *original* worker identity with the same shared `assertNativeWorker` used by
the CLI, for both `live` and `finished` states. An explicit identity mismatch
(`process_replaced`) takes precedence over lost/removed/restarted/finished events
**and** over stop attribution: a replacement is never excused by stop intent and
still faults, quarantines and retains the writer lease. A recorded `stop:` meta
with an accepted dispatch turns a matching validated native exit into
`intentionalStop` (releases the writer, marks the observation `stopped:true`,
writes the single `agent.stopped` audit row and one lifecycle attention notice
for the task's exact chat, never a runtime attention incident). The bridge does
not confirm on a bare disappearance or an unknown state: only an observed
`finished` exit for the validated original, a durable `stop.state==='confirmed'`,
or its own prior confirmation releases the lease. A `finished` exit observed
while a kill is still `dispatching` settles conservatively as `unattributed` on
the first observation. Unrecorded absence still faults, quarantines and retains
the lease.

The package owner's full run in a clean environment (where the bridge's private
Unix socket may be bound) is the authoritative result for this release:
**560 tests, 557 pass, 3 skip, 0 fail, exit 0**, covering the delegation,
routing, store, activity-wait, bridge IPC and plugin-manifest/doctor suites.

- `node --check` passes on every changed `src/` and `tests/` file.
- `node --test tests/delegation.test.mjs` exercises the request ledger and
  lifecycle: separate delivery receipts, confirmed-vs-unobserved interrupt, stop
  intent/dispatch/exit/lease, idempotent stop retry without a second kill, stop
  available while an unresolved assignment exists, a failed or refused kill
  leaving durable evidence without a fabricated intentional stop, identity
  verified before the signal (a replaced process is never killed), the first stop
  request owning the signal (a different request ID is refused without a second
  kill), a dispatched signal before a vanished terminal not proving exit, a
  stopped original keeping readable history while later input is refused, and the
  two-part claim-ordering regressions (an inline uncertain message blocking a
  follow-up, an earlier prepared assignment never blocked by a later one).
- `node --test tests/routing.test.mjs` and `node --test tests/store.test.mjs`
  pass and pin the shared native-identity validator and the transactional store.
- New `tests/activity-wait.test.mjs` tests assert that the stop lifecycle events
  are in `DEFAULT_ACTIVITY_TYPES` and that a manager's own send is excluded from
  the default wake set.
- New `tests/bridge.test.mjs` tests cover stop-intent routing and
  original-process identity precedence at the bridge level (changed pid with lost
  and removed events, swapped task/desk labels and argv, an adopted finished
  mismatch, and a matching original confirmed once). Focus runs drive
  `checkWorker` directly with an injected RPC client and need no bus; the
  remaining bridge-routing tests bind the private Unix socket (see boundary
  below).
- A local harness (`src/bridge.mjs` with an injected RPC client, no live bus) and
  an independent direct probe reproduced the routing outcomes: a matching
  original finished after an accepted stop confirms once, releases the lease and
  emits one lifecycle notice (a replay adds nothing); a changed pid/label/argv
  with a lost, removed or finished event faults `process_replaced`, quarantines
  and retains the lease; a missing terminal with an unconfirmed (not-dispatched)
  stop intent stays unconfirmed and never latches a terminal `stopped` state; a
  missing terminal with a confirmed stop state is recorded stopped; missing
  without intent → fault `terminal_removed` + lease retained; an in-flight kill
  with an observed finished exit → `unattributed`, never `confirmed-stopped`.

Where a review sandbox forbids binding the bridge's absolute Unix socket
(`listen EPERM`), the IPC-dependent suites cannot complete there and fail only
with that sandbox error; their focused, socket-free name-pattern runs and
`node --check` still pass. That is a limitation of the sandbox, not a code
defect, and the clean full run above is the release result.

## Native-capability boundary (documented, not invented)

- A `sent`/`native-injected` receipt proves only native transport acceptance. The
  local installation exposes no API that proves the model consumed the input, so
  consumption is never claimed; reconciliation requires observed evidence.
- `terminal.kill` is already used by the reviewed `src/desk-runs.mjs` retire and
  cancel paths, so it is an established lifecycle API. It is not listed in
  `src/capabilities.mjs` `REQUIRED_CORE_METHODS` (only `terminal.interrupt` is);
  stop therefore guards the call against a `not_found`/identity mismatch and
  treats a missing response as an unconfirmed stop rather than a success. It is
  left out of the required-core contract so older installations that support
  interrupt but not kill are not rejected wholesale.
- Local sandbox note: a review sandbox may forbid binding the bridge's absolute
  Unix socket (`listen EPERM .../herdr-activity-*/<hash>.sock`), so the
  IPC-dependent suites (`tests/bridge.test.mjs`, `tests/activity-wait.test.mjs`,
  `tests/agent-tools.test.mjs`) cannot complete there. Run
  `node --test tests/*.test.mjs` where the socket may be bound; in a clean
  environment the full suite passes (see Verification).
