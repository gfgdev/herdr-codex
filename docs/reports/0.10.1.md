# 0.10.1 — reconnection, Goose envelope strictness and compaction qualification

This is a **patch release**. It adds no new public `complete_agent`/workspace API, enables
no automation and does **not** activate compaction. It firms up two boundaries (RPC
reconnection and native Goose envelope parsing), adds qualification evidence for the manual
compaction slice, and packages one existing document.

## What shipped

### Next-explicit-request RPC reconnection (`src/rpc-connection.mjs`)

A single logical RPC endpoint lazily opens one native `hc connect` connection. Once that
connection has closed, the next **explicit request** opens exactly one replacement.

- The request that observed the closure is **never replayed**. An in-flight mutation may
  already have reached Herdr, so the caller keeps the original uncertainty and decides
  whether to retry; the integration does not silently re-send after a possibly-lost receipt.
- Concurrent calls that arrive after a closure share the one replacement connection.
- A late close from an already-replaced connection cannot discard the newer one (the close
  handler only releases the slot when the closing client is still the current one).
- `createClient` is injectable so tests can drive close ordering a real `hc connect` process
  cannot produce deterministically; production uses the real `HerdrClient`.

### Strict native Goose JSON envelope (`src/compaction-service.mjs`)

The compaction adapter's Goose extractor accepts only the captured native JSON envelope and
requires a **paired successful tool-result**:

- the `recipe__final_output` request must be parsed (`toolCall.status: "success"`) **and**
  its matching `toolResponse` must be present, in order, `status: "success"`, and carry a
  well-formed native `value` body — a success status alone is not enough;
- **earlier explicitly failed result pairs may precede the unique later successful pair.**
  Those earlier failures are tolerated and skipped, and their failed outputs are **never**
  accepted; only the unique successful pair is used. An earlier parsed-but-failed pair does
  **not** reject the whole run;
- rejected, absent, duplicated, out-of-order or conflicting pairs are refused by name
  (`goose_final_response_*`, `goose_final_output_ambiguous`, …) rather than unwrapped;
- resolved runner errors keep their structured `code`/`detail`/exit evidence, and the service
  reports **actual runner calls** in `attempts` (honoring retryability per code) instead of
  the exhausted loop counter.

### Manual Goose→Pi compaction qualification (evidence only)

`docs/compaction-live-qualification.md` records a manager-observed **manual** Goose→Pi append
and persisted reopen (`inputs/qualification/pi-append-reopen.json`) and a separately observed
fresh, no-tools Pi continuation (`inputs/qualification/pi-live-continuation.json`). It ships
as documentation: the packaged plugin now includes that document, and **no** private runtime
or evidence is copied into the artifact.

**Scope of the claim.** It qualifies a **synthetic manual case only** — a small hand-built
history, not a near-limit context. Production extension hooks remain **dormant**; there is no
automatic/near-limit guarantee and no usage-savings percentage. The scripted Goose run is a
reproducible procedure whose output is model-dependent; only the in-process stub SDK boundary
tests are deterministic.

### Packaging (`scripts/build-plugin.mjs`)

- `docs/compaction-live-qualification.md` is added to the explicit packaged-document list.
- The version bump to `0.10.1` is mirrored in `package.json` and `plugin/plugin.json`; the
  builder still requires the two manifests to agree.

## Environment recovery (not a portable feature)

The manager's local runtime launcher required a **physical-path repair** in its own
environment. This was environment recovery for that host only, not a portable code feature,
and nothing in this release changes launcher resolution for other hosts.

## Boundaries (documented, not invented)

- RPC reconnection preserves caller uncertainty; it does **not** claim the lost operation
  succeeded or failed, and it never performs a silent second mutation.
- The Goose extractor is strict parsing of the **captured native** format; it is not a
  guarantee about model output quality and does not activate compaction.
- Packaged compaction example assets remain dormant examples; live qualification and explicit
  durable asset selection remain required.
- The main source checkout and prior workers remain preserved; this isolated checkout is the
  release source.
