# Herdr–Codex 0.3.0: delegation and testing report

Implemented and installed on November 13, 2026. The global plugin is ready for a new-chat test. Codex remains the manager; Pi and Goose run in native Herdr sessions against the existing Modal profile. OPA is unchanged.

## What is built

| Manager operation | Herdr interface | Behavior |
|---|---|---|
| Delegate a subtask | `delegate` | Registers a persistent agent, freezes its assignment/context/template, launches the native harness, waits for readiness and delivers its first instruction. |
| Continue an agent | `agent followup` | Reuses its existing terminal/session and includes queued notes exactly once. Optional new context supplements the conversation. |
| Send a note | `agent message` | Delivers conditionally to a working agent; otherwise queues without starting an idle agent. `--mode queue` always queues. |
| Inspect a team | `agent list` | Filters by chat, task or parent and separates task, launch and request states. |
| Read the terminal | `agent read` | Returns native text and process state; no screenshots or vision. |
| Wait for activity | `agent wait` | Subscribes to the existing bridge over acknowledged local IPC and reads the durable journal. No status polling, scheduled checks or inference calls. |
| Interrupt | `agent interrupt` | Requests native interruption, records its result and preserves the session/lease. |
| Recover delivery | `agent request`, `recover`, `reconcile` | Exposes saved intent and uncertainty; never blindly repeats a lost launch/send receipt. |
| Reuse instructions | `template list`, `show`, `install` | Five built-in templates and explicit private user templates, with no provider/model overrides. |
| Full native control | `native …`, `app …` | Retains the native CLI and desktop capabilities beyond these convenience operations. |

The built-in templates are **explorer**, **implementer**, **reviewer**, **tester** and **investigator**. Their instructions and default read/write scope are stored with each delegation. They are starting points, not a mandatory team or review pipeline.

Context handoff accepts explicit Markdown/text or structured JSON with summary, decisions, constraints, acceptance checks and references. It stores exact source-byte hashes and content. References are labels, not automatic file attachment. Later edits to a context/template file do not rewrite an existing assignment.

Stable agent and request IDs make retries idempotent. A different payload under the same ID fails. Delivery states distinguish queued, prepared, sending, sent, failed and uncertain. A sent native receipt does not mean the model has processed the request. Unknown delivery requires evidence before reconciliation.

One writer per checkout is enforced inside the SQLite reservation transaction, including writers requesting disjoint paths in the same checkout. Multiple read-only agents can share a checkout. Concurrent writers need separate checkouts. These controls do not discover unrelated external processes or sandbox the complete native Herdr API.

## The game-space confusion and fix

The trial’s `show` commands originally placed its two agents in the desktop’s selected **Lanternfall · game studio** space. Their actual working directory was the private Relayboard copy; the game builder was not resumed. This was a presentation mistake caused by native default placement.

The test tab was closed after its evidence was saved. The game builder retained its original PID and idle/done state. The other game tabs were left intact.

`show` now resolves a space whose canonical folder matches the worker’s checkout. It rejects a missing, ambiguous or unrelated space, checks the actual checkout of split anchors, and detects observable focus races. If no matching space exists, create one explicitly before showing the worker. It never silently falls back to the currently selected game or other project.

The seven queued Codex messages came from this trial, not the game. A plugin acknowledgement does not withdraw a message already queued in Codex. The exposed host queue API has no withdrawal operation. Delayed delivery must reconcile the saved decision, not launch or repeat work. This remains a visible UX limitation; reducing queued-notification clutter is follow-up work.

## How to test in a new chat

Open a new Codex chat in the desired project and say:

> Use the Herdr plugin for this task. Delegate the implementation to Pi and an independent review to Goose. Give both the relevant context, let them consult each other, and continue the same sessions for revisions. Show them in a Herdr space for this project. Verify the result before accepting it.

Choose a small real task first. Codex should inspect the existing team, preserve the selected Modal model, create stable IDs, and use the `delegate` interface. You do not need to supply CLI commands or recipes.

To test continuation, send:

> Continue the same Pi agent with this change: [change]. Keep the earlier constraints, and have the existing reviewer check it.

To test a queued note:

> Queue this note for Pi’s next explicit follow-up without starting it now: [note].

Then explicitly ask it to continue. Queued notes are not drained by direct native typing, a peer message or the legacy `message reply` command.

To inspect activity, ask for the roster or actual terminal text. While workers run, Codex can yield; the existing bridge returns addressed questions, results and relevant lifecycle attention to the bound chat. A bounded `agent wait` is also available during an active turn. Its timeout leaves workers running.

## Opening and watching native Herdr

Ask Codex to open Herdr, or use the installed wrapper’s `app` command. The desktop shows native sessions, not a recreated dashboard. Codex reads structured status and terminal text.

For CLI use, replace the placeholders below with actual returned IDs and absolute paths:

```sh
herdr-codex app
herdr-codex app ls
herdr-codex app do space.new --name "My project" --folder /absolute/project
herdr-codex show --worker AGENT-ID --space SPACE-ID
herdr-codex show --worker REVIEWER-ID --space SPACE-ID --place right
```

A space creation also creates its native initial shell/tab. Reuse a matching existing space when appropriate. Verify the final layout with `app ls`; `pending` is not confirmation that placement is complete.

Herdr’s **Idle** section includes retained agents whose processes remain open but are not working. `live` means the process exists; `working`, `done` and `idle` describe its turn state. Neither an open pane nor a completed turn proves task correctness. Closing a worker pane/tab ends its terminal; merely closing the desktop window preserves workers according to native lifecycle rules.

## Limits and next work

- This is a CLI delegation interface; it does not intercept Codex’s built-in `spawn_agent` implementation.
- Exact conversation forks are unavailable. Context handoff is explicit selected content.
- `--parent` records a relationship, not automatic recursive provisioning by workers. Codex can provision the team and give peers their native addresses.
- Pi here is the native Pi CLI, not Pi Durable. Each harness retains its own persistence, steering and cancellation behavior.
- An interrupted model turn does not prove every subprocess ended. Inspect the native result and actual processes before changing checkout ownership.
- A worker crashing between journal commit and notification can delay an in-turn wait until recovery or its deadline; the durable event remains stored. A bridge disconnect fails visibly instead of polling.
- Prior 0.2.1 testing demonstrated actual post-turn wake in this host. This release verified the unchanged host-dispatch path with real queued trial messages while Codex was active, plus isolated native lifecycle tests. It did not repeat an additional fresh idle-chat wake after installation.
- Model output still requires review. The two inaccurate preflight explanations in this trial demonstrate why successful communication is not equivalent to reliable judgment.

The next useful improvement is notification coalescing/reconciliation so an active manager does not leave a stack of already-handled messages in the host queue. A later extension can add explicitly authorized worker-created child delegations; neither should weaken durable routing or ownership checks.
