# 0.8.0 — native-style Herdr subagent tools

Implemented and locally installed on 2026-11-13. Superseded by the 0.8.1 release note,
which traces the tool-discovery failure recorded below to a
non-plugin-relative command in `mcp.json` and adds `show_agent` (ten tools). The
counts and observations here remain the record of the 0.8.0 build.

## Changes

- Nine structured MCP tools over existing delegation, requests, writer leases,
  notification handling and bridge IPC. See [the adapter guide](../agent-tools.md).
- Stable chat/task identities and automatic retry keys; explicit keys permit
  intentionally repeating identical instructions.
- Concurrent waits, transport cancellation and durable mutation receipts.
- Explicit context briefs; configured provider/model preserved.
- Compact terminal metadata and native identity verification before reads.
- Idempotent acknowledgement retries without contacting a completed worker.
- Portable `mcp.json`, launch script, updated skill and source-only packaging.

## Verification

Final `npm test` exited 0: **488 tests, 485 passed, 3 skipped, 0 failed**.
The adapter adds 13 tests covering MCP discovery, errors, concurrent calls,
cancellation and EOF; durable spawn/send retries; context freezing; wrong-chat
operations; queued messages; retained writer leases; bridge activity/cursors;
notification receipt; acknowledgement guards and replacement terminal identity.
Local socket tests required an IPC-enabled execution context; the restricted
sandbox's `EPERM` was an environment failure, not a passing test.

The packaged and installed servers were connected with the official MCP SDK
client already present in the workspace. Initialization and all nine tool
definitions were discovered. A real read-only Goose reviewer was launched through
`spawn_agent`; live listing, waiting, terminal reading, messaging, notification
receipt, reply-plus-acknowledgement and final acceptance were exercised against
the existing bridge. Follow-up/interrupt behavior has regression coverage; those
two tools were not separately exercised on a live worker in this qualification.
The selected provider/model was unchanged. Review reports were inspected and
acknowledged, and the review task was closed.

The reviewer initially proposed coercing cancellation IDs and replying after
cancellation. Those proposals were rejected against the
[MCP cancellation requirements](https://modelcontextprotocol.io/specification/2025-06-18/basic/utilities/cancellation)
and [JSON-RPC identifier semantics](https://www.jsonrpc.org/specification).
Typed request IDs remain distinct; cancelled responses are suppressed. Already
dispatched mutations retain their durable receipts. Mixed Desk/project inputs
now reject explicitly. The reviewer checked the final sources and reported no
open findings, but could not run socket-based tests inside its restricted worker.
Codex performed the successful full regression run independently.

The package build verified document links, private-content exclusion, packaged
CLI help and packaged MCP discovery. The installed 0.8.0 server returned its
version, all nine tools and the existing chat's actual Herdr agent state.

## Qualification limits

The current Codex chat's tool catalog did not hot-refresh after installation.
Direct model invocation of the newly installed tools therefore still requires
host tool reload/reconnection or a new chat. MCP client execution is verified;
host-level discovery in a refreshed chat is not yet observed.

The existing bridge delivered real report notifications into the current chat's
queue, and the adapter received and acknowledged them. A fresh post-turn idle-chat
wake trial was not performed for this release; bridge wake implementation did not
change. Exact conversation forks and interception of native collaboration calls
remain unsupported. No hook was installed, and nothing was committed or published.
