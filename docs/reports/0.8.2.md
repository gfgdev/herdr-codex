# 0.8.2 — durable runtime retention

Implemented and verified on 2026-11-13. Supersedes the 0.8.1 release note. No provider,
model, bridge lifecycle, writer-lease, notification or native-CLI behavior
changed; the integration runtime is now pinned to an immutable snapshot under the
state directory instead of the disposable installed plugin cache.

## Reported problem

A Codex plugin install/upgrade pruned the old version cache directory. A live
Goose reviewer (`t1r`) had `worker.json.packageRoot` pointing at the pruned
`<cache>/0.8.0/runtime`; its Stop hook script and `herdr-message` helper
disappeared, so the running session could no longer report results or answer
questions. The manager restored the exact old `0.8.0`/`0.7.0`/`0.2.1` release
directories to recover that live session. New work must not depend on a path a
host upgrade can delete.

## Root cause

`config.packageRoot` was the installed package directory itself. Every durable
reference — worker helpers and argv (`src/workers.mjs`), the Goose Stop hook and
recipes and message reporting (`src/worker-launch.py`), delegation
(`src/delegation.mjs`), the notification inbox (`src/notifications.mjs`) and the
detached bridge child (`src/cli.mjs` → `src/bridge.mjs`) — embedded
`packageRoot/src/...`. When the host pruned the cache, all of those references
became dangling at once.

Root cause was reproduced rather than inferred: a worker launched from a cache
directory kept working until that directory was removed, at which point its
`bin/herdr-message` and Goose Stop hook failed with `ENOENT`.

## Changes

- New dependency-free `src/runtime-snapshot.mjs` publishes an immutable,
  source-only snapshot under the configured state directory before the first
  command of a process runs:

  ```
  <stateDir>/runtime/v1-<content-key>/
    manifest.json      # snapshot version, content key, per-file sha256/bytes
    src/*.mjs, *.py    # exactly the shipped integration sources
  ```

  The snapshot copies only the shipped `.mjs`/`.py` integration sources,
  matching `scripts/build-plugin.mjs`. It never copies credentials, model or
  provider binaries, user state or unrelated files.
- Content addressing: the key is `v1-<sha256>` over the sorted source path/digest
  set, so identical runtimes reuse one directory and changed sources publish a new
  one. Reuse revalidates the recorded manifest and every file digest; a tampered,
  extended, corrupt or symlink-substituted snapshot is refused rather than
  trusted (`Immutable runtime snapshot does not match its recorded content: …`).
- Atomic publication: sources are written into a `.staging-<uuid>` directory,
  `fsync`ed, then `rename`d into place. Files are mode `0o400` and directories
  `0o500`. A losing concurrent publisher re-inspects the destination and accepts
  it iff it validates for exactly this content, otherwise throws
  (`Concurrent runtime snapshot publication produced a different result: …`); it
  removes only its own staging directory, restoring write permission first, and
  never mutates the winner.
- Pinning: `src/cli.mjs` and `src/agent-tools-runtime.mjs` set
  `config.runtimeRoot` to the snapshot and override `config.packageRoot` to it
  after the snapshot is published. All existing `packageRoot` consumers therefore
  resolve inside the immutable snapshot:
  - worker helpers/argv and `worker.json` (`src/workers.mjs`),
  - Goose Stop hook and recipes and message reporting (`src/worker-launch.py`,
    bakes the hook to `packageRoot/src/goose-status.py`),
  - delegation (`src/delegation.mjs`), desk commands (`src/desk-commands.mjs`),
    adoption (`src/adoption.mjs`), agent tools (`src/agent-tools-runtime.mjs`),
  - the notification inbox (`src/notifications.mjs`) and the wake text/child
    (`src/bridge.mjs`), which launch `config.packageRoot/src/cli.mjs`.
- Bridge: the detached bridge is spawned from the pinned
  `config.packageRoot/src/cli.mjs`. Its lock file, ownership and lifecycle are
  unchanged; no duplicate or restart is triggered by publication.

## Legacy sessions

Sessions launched before 0.8.2 keep their existing paths until they drain. They
are not retroactively migrated, because their launch files already embed the old
`packageRoot`. Let such a session finish, then start new work so it binds to the
durable snapshot. Treat the installed cache directory as disposable only after
any legacy session has drained. `docs/configuration.md#durable-runtime` states
this operationally.

## Fixture cleanup note

The immutable snapshot (`0o400` files, `0o500` directories) makes a plain
`rmSync(tmpTree, { recursive: true, force: true })` fail with `EACCES` because
removing directory entries requires write permission on the containing directory.
Tests that own a fixture tree containing a snapshot restore write permission
first (a test-local `writableTree()` chmods directories to `0o700` and files to
`0o600`, skipping symlinks) and then delete it. Production immutability is
unchanged; only test-owned temp trees are made writable before teardown.
